Build EPUB ebooks and PDFs from Markdown.

mdbindery turns Markdown chapters or mdBook projects into EPUB 3 ebooks or paginated PDFs. Both formats share chapter links, citations, images, Mermaid diagrams and table conversion. EPUB runs EPUBCheck and DAISY Ace; PDF checks resources, links and extracted text. Review reports and layout before sharing.

EPUB remains the default. PDF export is available with the optional pdf extra. Set up PDF export.

Capabilities

Keep your Markdown book workflow

Write and review chapters on GitHub. Both formats share source preparation and local assets; output checks and layout depend on the selected format.

Chapter links

Chapter links and anchors

Relative links between chapters, links to headings in other files, .html links pointing to .md chapters, and custom <a id> anchors become internal book links. Any broken internal target fails the build when strict_links is enabled.

References

Visible reference lists

Citations written as [1] paired with [1]: url "Title" reference definitions (which are invisible on GitHub) become a visible, numbered reference list at the end of the chapter with working links. Footnotes become numbered endnotes.

Book assets

Images and covers

Images automatically become inline icons, block images, captioned <figure> blocks (from the image title), or dedicated full-page images ("full-page" title). Supply any supported image format for the cover or let mdbindery generate a 1600×2560 typographic cover from book metadata.

Diagrams and math

Mermaid diagrams and MathML

Fenced ```mermaid diagrams render to PNG images via mermaid-cli with automatic alt text extracted from the chart labels. TeX formulas convert to MathML for EPUB readers and Chromium PDF rendering.

Small screens

Wide tables as row cards

For files listed under options.cards.files, wide Markdown tables (options.cards.min_columns, default 9 columns) transform into vertical per-row card blocks with repeated header labels so they read cleanly on a phone.

GitHub formatting

GitHub formatting and HTML

GitHub alerts (> [!NOTE]), task lists, monochrome code syntax highlighting, and supported raw README HTML (<br>, <sup>, <img>, <p align>, <details>) pass through shared cleanup for EPUB and PDF; unsupported tags are removed and reported.

mdBook

Read existing mdBook settings

For mdBook projects, book.toml supplies book metadata, SUMMARY.md sets the reading order, {{#include}} directives expand with cycle and size limits, and hidden Rust lines are stripped.

PDF export

Paginated PDF

Choose A4 or Letter pages, margins and page numbers with options.pdf. Export uses installed Chromium and shared book styles with print overrides. Inspect pagination and glyphs; PDF/A, PDF/UA and print-production readiness are not claimed.

Deterministic

Reproducible EPUB builds

Building the same Git commit twice with the same tools, fonts, and a saved metadata.identifier produces byte-identical .epub files. EPUB metadata includes a publication identifier and schema.org accessibility information.

Installation

Install on Linux, macOS, Windows, or CI

The installers need no preinstalled Python, Java, or Node.js and no administrator rights. Linux and macOS need Bash, curl, tar, and standard checksum utilities; Windows needs PowerShell. Tools are installed in your user directory. Once installed, local builds work offline. See tool versions and verification.

Linux & macOS

Installs mdbindery to ~/.local/bin and managed tools to ~/.local/share/mdbindery (macOS: ~/Library/Application Support/mdbindery):

curl -fsSL https://raw.githubusercontent.com/sagol/mdbindery/main/install/install.sh | bash

Pin a specific release tag or pass --no-node to skip Node.js tools (~370 MB instead of ~1.5 GB):

curl -fsSL https://raw.githubusercontent.com/sagol/mdbindery/v0.2.0/install/install.sh | bash -s -- --ref v0.2.0

Windows PowerShell

Installs to %USERPROFILE%\.local\bin (added to user PATH) and tools to %LOCALAPPDATA%\mdbindery:

irm https://raw.githubusercontent.com/sagol/mdbindery/main/install/install.ps1 | iex

PyPI (uv / pipx)

Install the Python package from PyPI with uv or pipx, then install the companion tools:

uv tool install mdbindery
mdbindery install-tools
mdbindery doctor

Homebrew (macOS & Linux)

Install from the Homebrew tap on macOS or Linux, then run install-tools:

brew install sagol/tap/mdbindery
mdbindery install-tools
mdbindery doctor

GitHub Actions

Use the official composite GitHub Action with tool caching across workflow runs:

- uses: sagol/mdbindery@v0.2.0
- run: mdbindery build path/to/book

Optional PDF export

Install version 0.2.0 or newer with the PDF extra in your Python environment:

python -m pip install 'mdbindery[pdf]>=0.2.0'
mdbindery install-tools
mdbindery build ./my-book --format pdf

PDF needs Node.js, Puppeteer and pypdf. An install with --no-node cannot export PDF. doctor checks the EPUB toolchain; it does not verify pypdf. See the PDF guide.

Downloaded uv, pandoc, EPUBCheck, and Node.js binaries are checked against pinned SHA-256 checksums. Java uses a suitable installed runtime or the latest Temurin 21 build, verified with the checksum returned by its API. Mermaid-cli and Ace have pinned top-level npm versions; their dependencies resolve during installation.

Build checks

Validation for each output format

Both formats check links, images, charts and includes. EPUB adds EPUBCheck, Ace and per-chapter word counts; PDF adds resource, internal-link and extracted-text checks. Reports use dist/reports/build.json for EPUB or dist/reports/pdf/build.json for PDF. The includes entry appears only on failure. A failed gate returns status 1.

links · Both Gate

Fails on unresolved internal chapter anchors or links to missing files when options.strict_links is true (default); warns when false.

images · Both Gate

Fails when an image is missing, remote (http://, https://), empty, or (for untrusted repositories checked by URL) outside the repository checkout.

charts · Both Gate

Fails when a ```mermaid block fails to render. Warns (using chart placeholders) if mermaid-cli is missing while options.mermaid is png.

includes · Both Gate

Reports failed mdBook {{#include}} expansions (missing file, cycle, or size limit). The includes gate appears in build.json only with result: "fail". It is omitted when no include directive fails; no pass entry is emitted.

epubcheck · EPUB Gate

Runs W3C EPUBCheck v5.4.0 (unless options.epubcheck: false). Fails on any FATAL or ERROR message or if EPUBCheck cannot run.

ace · EPUB Gate

Runs DAISY Ace 1.4.6 (skipped with --no-ace or options.ace: false; warns if Ace is not installed). Fails on unwaived critical or serious violations.

wordcount · EPUB Gate

Fails if any chapter's EPUB word count differs from its prepared Markdown source by more than 2% (wordcount_tolerance) and 25 words (wordcount_min_words).

pdf · PDFGate

Checks loaded resources and internal links, then compares extracted PDF text with generated HTML using the configured word-count tolerances. A readable PDF with failed text checks remains available for inspection. Renderer errors preserve an older PDF. Scripts are disabled and unstaged resource requests are blocked. PDF never automatically disables the browser sandbox.

Agent integration

Agent skills and JSON reports

mdbindery ships with self-contained SKILL.md instructions and structured JSON reports so AI coding agents (Claude Code, OpenAI Codex, Cursor, Google Antigravity, Gemini CLI, Windsurf, Aider) can inspect, repair, build, and preview Markdown book repositories.

Skill 1: mdbindery Run and validate

Instructions for installation, tool checks, configuration, builds, and previews. Run mdbindery check . --json check.json for a local book, or replace . with a repository URL. Review reports and screenshots before publishing.

Instructions to resolve MB001–MB904 findings in a Markdown repository or mdBook: reading order, headings, anchors, [1] citations, alt text, wide tables, and raw HTML. Preserve the author’s meaning and GitHub rendering when making changes.

Configuration

Configure your book with mdbindery.yaml

Every key in mdbindery.yaml is optional. Run mdbindery init to generate a starter configuration from your repository, or keep your book repository untouched by placing mdbindery.yaml in a separate folder with source_dir.

Sample book configuration with PDF defaults YAML 
slug: writing-a-book-in-markdown
output_dir: dist
source_url: https://github.com/sagol/mdbindery/blob/main/examples/sample-book/

metadata:
  title: Writing a Book in Markdown
  subtitle: A small sample book for mdbindery
  authors: [Sample Author]
  lang: en-US
  identifier: urn:uuid:5f0f1c2e-8a4b-4d6e-9c1a-3b7e2d9f0a11
  date: 2026-09-26
  rights: Text and images licensed under CC BY 4.0
  description: A short book that demonstrates every feature of mdbindery.
  subjects: [Markdown, EPUB, Publishing]

cover:
  image: images/cover.jpg

files:
  - file: README.md
    role: front
    title: About this book
    drop_sections: [Contributing]
  - 01-why-markdown.md
  - 02-structure.md
  - 03-publishing.md
  - file: appendix-a-checklist.md
    role: appendix

options:
  citations: refdefs
  toc_depth: 2
  pdf:
    page_size: A4
    margin_mm: 20
    page_numbers: true
  cards:
    files: [appendix-a-checklist.md]
    min_columns: 9
    title_columns: 2

Build the sample book

From a checkout of the mdbindery repository, build the included sample book:

mdbindery doctor
cd examples/sample-book
mdbindery check . --build
mdbindery build
# After installing PDF dependencies
mdbindery build --format pdf
mdbindery preview dist/writing-a-book-in-markdown.epub shots

PDF writes dist/<slug>.pdf and dist/reports/pdf/{build.json,build.log}. EPUB and its reports remain available. The cover image is shared; PDF reports add Chromium/Puppeteer versions. PDF bytes are not guaranteed reproducible. preview accepts EPUB only.

Build files and provenance

Completed EPUB builds write dist/<slug>.epub, dist/<slug>-cover.jpg, dist/reports/build.json, and dist/reports/build.log, plus dist/reports/epubcheck.json and dist/reports/ace/report.json (and report.html) when those validators produce reports. A build that stops early may leave only failure diagnostics. build.json records provenance (mdbindery, python, pandoc major.minor, epubcheck, and ace versions, source Git commit, and effective options), per-stage timings, and gate states (pass, warn, fail, skipped).

Help

Frequently asked questions

Can I export PDF as well as EPUB?

Yes, with version 0.2.0 or newer, the pdf extra and Node/Puppeteer tools. Use mdbindery build --format pdf. EPUB remains the default. PDF reports live in reports/pdf/; EPUBCheck and Ace apply only to EPUB.

What makes mdbindery different from running pandoc directly?

mdbindery uses pandoc for conversion and adds a book workflow around it. It resolves chapter links and anchors, turns numeric reference definitions into visible reference lists, renders Mermaid diagrams, and converts wide tables into row cards for configured files. It also runs configured validation gates and records their results.

Does mdbindery support existing mdBook repositories?

Yes. When a folder contains book.toml and SUMMARY.md, mdbindery automatically reads the title, authors, description, and language from book.toml, takes the chapter reading order from SUMMARY.md, expands {{#include}} directives (with cycle and size limits), and strips hidden lines in Rust code blocks.

How can coding agents use mdbindery?

Point Claude Code, Codex, Cursor, or Antigravity at llms-full.txt and the two official skills in skills/mdbindery/SKILL.md and skills/mdbindery-prepare-repo/SKILL.md. The agent can run mdbindery check . --json check.json, fix reported findings by file and line number, and verify the final ebook with mdbindery build and mdbindery preview dist/<slug>.epub shots.

What do I need to install mdbindery?

The installers need no preinstalled Python, Java, or Node.js and no administrator rights. Linux and macOS need Bash, curl, tar, and standard checksum utilities; Windows needs PowerShell. Tools stay in your user directory. Local builds work offline once installation is complete.
